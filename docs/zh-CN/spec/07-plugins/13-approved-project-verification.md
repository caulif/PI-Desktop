# 已批准的项目验证

> **翻译说明：** 本页是与 [英文源规格](/spec/07-plugins/13-approved-project-verification) 一一对应的机器辅助翻译。代码、协议字段和标识符保持原文；如翻译与英文源事实有歧义，以英文版本为准。

经过审查、仅限插件使用的操作包括 `verification/approveCheck`、`snapshot`、
`runApprovedCheck`、`lookupExecution`、`cancelExecution` 和 `revokeCheck`。
外部 MCP 不能调用这些操作。Main 从已加载的进程提供插件身份；插件参数不能携带
审批令牌、执行 claim 或授权标志。

审批使用 Main 的原生对话框，审批对象是 Host 生成的不可变定义。对话框展示规范化的
可执行文件、固定 argv、可执行文件和脚本的哈希、项目、插件拥有的会话、摘要、限制和
到期时间。关闭对话框即拒绝审批。挑战令牌由 Main 私有保存，且只能使用一次。
调用方的确认不构成原生授权。固定命令以操作系统账户权限运行，并非运行于操作系统
沙箱；传递依赖代码和可变 Unix 输入属于已记录的限制。

快照绑定已批准的命令身份、Git HEAD、已跟踪及未被忽略的工作树内容，以及实际使用的
白名单执行环境。输入改变、会话或项目不属于当前授权范围、授权到期或被撤销时，
均拒绝新的执行准入。

执行前先保存精确请求摘要和持久化 claim。并发的相同请求返回已有回执。响应未知或
冷启动后，仅查询原来的执行，不重新启动。启动时将失去执行协调者的执行中回执改为
`unknown`，并使对应的协调者 claim 失效。授权撤销或输入发生变化后，已有执行仍可
查询和取消。查询会校验已保存的精确请求，以及当前有效且由插件拥有的作用域。

Host 负责创建进程、清理环境、限制输出、超时、进程树所有权和取消。
取消意图不等于成功回执。执行完成必须具有实际测量的输出和执行后的快照；清理失败、
超时、输出截断、取消或测量缺失时，状态仍为未完成。执行退出成功不代表通过人工
内容审阅或工程审查。

Bot 会话使用 ADR 0323 描述的不可变、限定范围的工具策略。文件调用使用发起调用的
会话所绑定的项目；项目缺失时，不能借用可见窗口的工作区。目录列表会对目录及每个
返回的子条目应用 `realpath` 路径范围检查。
